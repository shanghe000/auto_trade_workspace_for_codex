# 上线路线图

## 阶段 0：纯分析模式

目标：

- 定清角色契约
- 定清风控模型
- 定清策略治理模型
- 定清飞书输出格式

规则：

- 不接真实凭证
- 不开 live 开关
- 只做市场观察和交易计划

退出条件：

- Bot 能清楚解释交易计划
- 证据不足时能稳定给出 `HOLD`
- 策略草案、审核、激活状态已经被定义清楚
- 飞书里的摘要格式足够清晰

## 阶段 1：交易所只读接入

目标：

- 验证账户快照、挂单快照、市场快照和事件基础链路

规则：

- 只能走只读路径
- 不允许下单、改单、撤单

退出条件：

- 账户余额能与 OKX 页面对齐
- 持仓和挂单能与 OKX 页面对齐
- 数据过期检测能稳定触发
- 关键订单 / 仓位事件已能被稳定捕获或补偿同步

## 阶段 2：模拟盘 / Demo 执行

目标：

- 打通 `TradeIntent -> 风控 -> 执行 -> 事件回流 -> journal -> report` 整条链路

规则：

- 只用模拟盘或 paper 模式
- 频率低
- 每次动作强制写 journal
- 执行前必须做二次校验

退出条件：

- 每笔订单都有稳定的客户端订单号
- 清楚了解重试和报错行为
- journal 可以支持回放和排障
- 成交事件可以重新唤起主 agent 继续处理

## 阶段 3：最小仓位实盘

目标：

- 在严格人工监督下开通最小可用实盘

规则：

- `live_trading.enabled = true`
- 仍要求人工确认
- 只允许 1 到 2 个白名单品种
- 杠杆上限严格受控
- 严格限制日内回撤

退出条件：

- 当天 journal 不依赖隐性知识也能看懂
- 成交与 PnL 对账稳定
- kill switch 路径已经被验证

## 阶段 4：半自动例行运行

目标：

- 允许通过 `cron`、心跳或事件触发运行低频观察、日报、对账和闭环处理

规则：

- 不进入无人值守高频交易
- 风控层仍然拥有 veto 权
- 重大变更仍保留人工复核路径
- 策略激活仍必须保留人工控制

## 这些步骤不能跳

- live 前必须先跑 dry-run 报告
- live 前必须确认精确白名单
- 必须检查时钟漂移
- 必须阻断过期数据
- 必须明确策略由谁审批与谁激活
- 执行后必须做交易所对账
